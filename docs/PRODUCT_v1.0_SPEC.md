# PrismOS 1.0 製品版仕様書 — 日常利用レベル

> **製品版の定義:** PrismOS 1.0 は、日常の PC として本格的なデスクトップ OS と同じレベルのことが
> できる、完成した OS である。起動して、ネットにつなぎ、ファイルを扱い、アプリを
> 入れて、仕事・勉強・遊びができる。初心者でも使えて、どこでもカスタムできて、
> セキュリティも最初からしっかりしている。
>
> **バージョンの整理:** 開発版は v0.1 → v0.9 と進み、v1.0 到達をもって製品版とする。
> ユーザーの「v10.0にて、製品版v1.0とする」は、この到達点を製品版 v1.0 と呼ぶ
> ものとして受け取った。もし番号の付け方を v10.0 にしたい場合は、ここだけ
> 読み替えればよい（中身は同じ）。
>
> **現状:** v0.1 は完成済み。C の最小カーネル + Limine 8.3.2 で QEMU 起動、
> シリアルシェルで 2 つの体系のコマンドが動くことをローカルで検証済み
> （`make test` 48 checks PASS、`make boot-test` BOOT TEST PASSED、ISO 3.8 MB）。
> この仕様書は、その v0.1 から v1.0 へ育てるための全リストである。
>
> **公式ロゴ:** 明るい版に決定（2026-11-21）。Canva デザイン DAHbf4AwTkU、
> 画像は `assets/logo-light.png`（2000x2000）。暗い版は不採用。
> README と起動画面ではこの明るい版を使う。起動画面では `kernel/logo.bmp`
>（640px 幅に縮小した 24 ビット BMP）を白い画面の中央に表示する。

## 1. 製品版 v1.0 の判定基準（これが全部できたら製品版）

| 観点 | 判定基準 |
|---|---|
| 起動 | 電源を入れて 30 秒以内にログイン画面、ログイン後 10 秒以内にデスクトップが使える |
| 日常利用 | ブラウザ、メール、文書作成、表計算、写真・動画再生、ファイル管理が追加ソフトなしでできる |
| 安定性 | 1 日 8 時間の連続利用でクラッシュしない。アプリが落ちても OS 全体は落ちない |
| 互換性 | 主要な USB 機器、Wi-Fi、Bluetooth、プリンター、外部モニターが挿すだけで動く |
| カスタム | テーマ・レイアウト・ショートカットを GUI だけで変えられ、元に戻せる |
| セキュリティ | 暗号化、権限管理、署名付き更新が既定でオン。初心者が何もしなくても守られる |
| 更新 | セキュリティ更新が自動で届き、再起動が必要な場合も日時を選べる |
| サポート | 日本語のヘルプ、設定内検索、トラブル時の復旧モードがある |

## 2. 機能一覧

### 2.1 デスクトップと UI

- モダンなデスクトップ：中央寄せタスクバー、スタートメニュー、システムトレイ、通知センター、クイック設定、ウィジェットボード
- スタート：ピン留めアプリ、検索、最近使ったファイル、おすすめ、フォルダー
- タスクバー：位置（下・上・左・右）、大きさ、アイコンの中央／左寄せ、時計・カレンダー、音量・Wi-Fi・バッテリー。既定は左寄せ（2026-11-20 ユーザー決定）
- ウィジェットボード：天気・ニュース・カレンダーを全部出す（2026-11-20 ユーザー決定）
- ウィンドウ管理：スナップレイアウト（左右・上下・4 分割）、スナップグループ、タスクビュー、仮想デスクトップ（作成・名前変更・壁紙ごとに変更）
- Dock と横断検索：Dock（位置・大きさ・拡大表示・自動で隠す）、横断検索（アプリ・ファイル・設定・計算・Web を横断検索）、ウィンドウ一覧（全ウィンドウとデスクトップを一画面で表示）、アプリ一覧。Dock は最初から表示する（2026-11-20 ユーザー決定）
- 通知：アプリごとの通知オン／オフ、おやすみモード、通知履歴
- ロック画面・ログイン：壁紙、時計、PIN・パスワード・指紋・顔認証（対応機器）、複数ユーザー切り替え。解除方法は全部使えるようにする（2026-11-20 ユーザー決定）
- ダーク／ライトモード、アクセントカラー、透明効果（アクリル／マイカ風）、角丸、影、アニメーションのオン／オフ。ダーク／ライトの切り替えは手動（自動切り替えはしない）（2026-11-20 ユーザー決定）
- マルチモニター：モニターごとの壁紙・タスクバー、解像度・拡大率・配置の記憶
- タッチ・ペン・ジェスチャー対応（対応機器）

### 2.2 ファイルとストレージ

- ファイルマネージャー：フォルダー、検索、プレビュー、タブ、分割表示、並べ替え、タグ、クイックアクセス、お気に入り
- ストレージ：内蔵・USB・外付け HDD/SSD、SD カード、ネットワークドライブ、クラウド連携
- 検索：ファイル名・中身・種類・日付での検索、インデックスによる高速検索
- 圧縮・解凍（zip など）、ごみ箱（復元・完全削除）、ファイル履歴・バックアップ
- ディスク管理：空き容量表示、クリーンアップ、ディスク暗号化の状態表示

### 2.3 標準アプリ（最初から入っているもの）— 2026-11-20 ユーザー決定

- Web ブラウザ：**自作ブラウザ「Prism Browser」**。Chromium ベースではなく、Firefox のような独立エンジン路線で作る。エンジンは一から作る（2026-11-20 ユーザー決定）。既定の検索エンジンは Google。拡張機能はなし
- メール、カレンダー、連絡先、メモ、時計・タイマー・ストップウォッチ：最初から入れる
- 文書・表計算・プレゼン：**独自のオフィスアプリ「Prism Office」**を作る（Office 互換ファイルを開けること）。Office 形式（.docx / .xlsx / .pptx など）との互換性も持たせる（開く・保存の両方）
- 写真（表示・整理・簡単な編集）、動画プレイヤー、音楽プレイヤー、カメラ、ボイスレコーダー：入れる
- 電卓、ペイント風お絵描き、テキストエディター
- 開発ツール：ターミナル、テキストエディター、Git、言語実行環境は一応最初から入れる（2.9 も参照）
- ゲーム：**シューティングゲームとトランプ**をプリインストール。シューティングは 3D。トランプは全部（ソリティア、神経衰弱、七並べ、ポーカーなど）。ゲームもアプリと同じストアで配布する
- 設定、ヘルプ、フィードバック
- ストア（アプリの検索・インストール・更新・レビュー。ゲームもここ）。名前は「Prism Store」。ストアのアプリは無料だけ。配信するのはこちらで用意するものだけ。出すのはこちら（PrismOS 側）のみで、外部の開発者は出せない（2026-11-20 ユーザー決定）
- いらない標準アプリはアンインストールできる。インストール時に最小構成だけ入れる選択肢も用意する。最小構成はブラウザとファイルマネージャーと設定だけ。入れるものはユーザーが選べる
- サードパーティ製アプリは最初からは入れない。ユーザーが自分で入れる。exe ファイルにも互換性を持たせたい。他の OS のアプリすべてに互換性を持たせるのが目標（5.2 も参照）。実現方法は Wine のように、他の OS のアプリをそのまま動かす互換層。他の OS のアプリ（.app / .dmg）も動かしたい

### 2.10 アップデート配信 — 2026-11-20 ユーザー決定

- セキュリティ更新と機能更新は分ける。セキュリティ更新は自動で届く。機能更新はユーザーが選んで入れる
- 更新チャンネルを選べる：安定版とベータ版。ベータを選んだ人だけ先行版が届く。ベータから安定版には戻れる（設定を残したまま）
- 再起動が必要な更新は日時を選べる、作業中は延期できる、アクティブ時間中は勝手に再起動しない
- 更新に失敗したら自動で前の版に戻る（ロールバック）。戻したことを通知する
- 差分更新にする（変わった分だけ落とす）。従量課金・モバイル回線では更新を止める配慮をする
- 配信元は GitHub Releases だけ。専用の更新サーバーは作らない
- OS の更新とアプリの更新は同じ画面で管理する
- バージョン番号は年号形式：**年 + H1 / H2**。例：24H2（2024 年下半期）、25H1（2025 年上半期）。開発版の v0.1 → v0.9 → v1.0（製品版）とは別に、製品版のリリース番号はこの年号形式で付ける。最初の製品版は 2027 年度上半期に出すので **27H1** とする（2026-11-20 ユーザー決定）

### 2.4 シェルとコマンド（2 つのコマンド体系に対応）

- ターミナル：タブ、分割画面、テーマ、フォント、コピー＆ペースト、履歴、補完
- `ls` 系コマンド：`ls` `cat` `pwd` `cd` `cp` `mv` `rm` `mkdir` `grep` `ps` `top` `chmod` `ssh` `curl` など
- `dir` 系コマンド：`dir` `type` `cls` `copy` `move` `del` `md` `tasklist` `ipconfig` など、同じ意味のコマンドは両方の名前で動く
- シェルスクリプト（2 つの体系の両方の基本文法）、環境変数、エイリアス
- パッケージマネージャー（例：`prism install <アプリ名>`）：アプリの検索・導入・更新・削除、依存関係の解決

### 2.5 設定とカスタマイズ（どこでもカスタムできる）

**初心者向け（GUI だけで完結）**

- 初回セットアップウィザード：3 つの質問で好みのスタイルを選ぶだけ
- ワンクリック・プリセット：「シンプル」「仕事用」「かわいい」「ダーク」「明るい」など
- モード分けはしない。かんたんモード／上級モードの切り替えはなし。1 つの本格的なデスクトップ UI で、既定値が分かりやすく、すべての設定が同じ設定画面から段階的に掘り下げられる（よく使う設定が上に、細かい設定が下に）。初心者でも迷わず、上級者も同じ画面で全部変えられる
- 変更はプレビューで確認してから適用、いつでも「元に戻す」「初期状態に戻す」
- 設定内検索：「壁紙を変えたい」と言葉で探せる

**変えられるもの（全リスト）**

- テーマ：色、アクセントカラー、壁紙（写真・動画・スライドショー）、フォント、アイコン、音、カーソル、アニメーション、透明度、角丸、影
- デスクトップ：アイコンの配置・大きさ、ウィジェット、仮想デスクトップの数と名前
- タスクバー／Dock：位置、大きさ、表示するアイコン、自動で隠す、時計の表示形式
- スタート：ピンの並び、表示するフォルダー、検索の対象
- ロック画面・ログイン画面・起動画面
- キーボードショートカット、マウス・タッチパッドのジェスチャー、右クリックメニュー
- アプリごとのテーマ、言語、通知、権限
- シェルの見た目（プロンプト、色、フォント）、ターミナルのテーマ

**上級者向け**

- 設定はすべて `config/theme.toml` などのテキストファイルでも変えられる（GUI と同じ内容）
- テーマファイルの保存・共有・インポート／エクスポート
- プラグイン／拡張機能：デスクトップの部品や機能を追加できる仕組み、公式ストアでの配布と署名チェック
- 自動化：起動時に開くアプリ、定型操作の記録と実行

**壊れないためのルール**

- カスタムで OS が起動しなくなっても、復旧モードから初期テーマに戻せる
- 設定変更は 1 つずつ保存され、失敗した変更だけ巻き戻せる

### 2.6 ネットワークと接続

- Wi-Fi（WPA2/WPA3）、有線 LAN、Bluetooth、モバイル回線（対応機器）
- VPN、プロキシ、ファイアウォール設定
- ファイル共有（LAN 内）、プリンター共有、近くのデバイスとの共有
- ネットワークの診断（接続できないときに原因を表示して直す手順を出す）

### 2.7 マルチメディアとデバイス

- 音声：スピーカー、ヘッドホン、Bluetooth オーディオ、マイク、音量ミキサー
- 画像・動画：主要な形式の再生（mp4、mp3、png、jpg など）、画面キャプチャ、画面録画
- カメラ・マイク：アプリごとの許可、利用中の表示ランプ
- プリンター・スキャナー：自動検出、ドライバーの自動導入
- USB・外部機器：挿すだけで認識、取り外しの安全な手順

### 2.8 アクセシビリティ（誰でも使える）

- 文字の大きさ、コントラスト、色覚サポート、画面拡大、スクリーンリーダー
- 音声入力、キーボードだけで操作できること、スティッキーキー、音声読み上げ
- 日本語・英語をはじめとする多言語表示と入力（IME）

### 2.9 開発者向け

- ターミナル、パッケージマネージャー、Git、主要なプログラミング言語の実行環境
- 仮想化・コンテナの基本対応、他の OS の環境を中で動かす仕組み（目標）
- ログと診断ツール、クラッシュレポート（送信するかどうかはユーザーが選ぶ）

## 3. 必要な構成

### 3.1 ハードウェア要件（v1.0 の目標）

- 対象は全対応が目標：デスクトップ、ノート PC。ARM 版も別で用意する（2026-11-20 ユーザー決定）。ARM 版は x86 版と同じタイミングで出し、機能も同じにする
- 言語は最初から選べる。初回セットアップで日本語・英語などを選ぶ（2026-11-20 ユーザー決定）。発売時の対応言語は日本語と英語

| 項目 | 最低 | 推奨 |
|---|---|---|
| CPU | 64 ビット、2 コア、1 GHz | 4 コア以上 |
| メモリ | 4 GB | 8 GB 以上 |
| ストレージ | 32 GB（SSD 推奨） | 64 GB 以上の SSD |
| グラフィックス | 1280×720、GPU 描画に対応 | 1920×1080 以上、GPU アクセラレーション |
| ネットワーク | 有線または Wi-Fi | Wi-Fi 6 |
| ブート | UEFI（BIOS 互換も維持） | UEFI + Secure Boot |

### 3.2 ソフトウェア構成（層で考える）

```
┌────────────────────────────────────────────┐
│ アプリ層：ブラウザ、メール、文書、設定、ストア      │
├────────────────────────────────────────────┤
│ デスクトップ環境：ウィンドウ管理、タスクバー、        │
│   Dock、横断検索、テーマエンジン、通知        │
├────────────────────────────────────────────┤
│ システムサービス：ログイン、権限、更新、バックアップ、 │
│   プリンター、ネットワーク、オーディオ、電源管理      │
├────────────────────────────────────────────┤
│ ライブラリ・ランタイム：グラフィックス、フォント、     │
│   マルチメディア、言語ランタイム、パッケージ管理      │
├────────────────────────────────────────────┤
│ カーネル：プロセス、メモリ、ファイルシステム、          │
│   デバイスドライバー、ネットワーク、セキュリティ      │
├────────────────────────────────────────────┤
│ ブート：UEFI / Limine、セキュアブート、暗号化解除      │
└────────────────────────────────────────────┘
```

### 3.3 各層の中身

- **ブート：** UEFI 対応、Limine（v0.1 で採用）からの発展、セキュアブート、ディスク暗号化の解除、復旧モードへの入口、起動ログ
- **カーネル：** プロセスとスレッド、スケジューラー、仮想メモリ、割り込み、システムコール、デバイスドライバー（ストレージ、USB、グラフィックス、ネットワーク、音声、入力）
- **ファイルシステム：** 起動用・ユーザー用・システム用の分離、ジャーナル、権限、暗号化、スナップショット／復元ポイント
- **グラフィックス：** フレームバッファ（v0.1 で寸法取得済み）→ GPU アクセラレーション、ウィンドウの合成（コンポジター）、フォント描画、HiDPI
- **サウンド：** ミキサー、デバイス切り替え、アプリごとの音量
- **ネットワーク：** TCP/IP、DNS、DHCP、Wi-Fi、Bluetooth、VPN、ファイアウォール
- **システムサービス：** ユーザー管理、ログイン、権限、電源管理（スリープ・休止・バッテリー）、時計、言語、更新、バックアップ、診断
- **パッケージと更新：** アプリと OS の署名付きパッケージ、差分更新、ロールバック（更新に失敗したら前の版に戻る）、更新の日時指定。配信元は GitHub Releases のみ。セキュリティ更新と機能更新は分け、ベータチャンネルも選べる（2.10 参照）
- **インストーラー：** USB からのインストール、言語・キーボード・ユーザー・暗号化の選択、既存 OS とのデュアルブート、インストール後の初回セットアップ。デュアルブートは別のタイプ（エディション）として作る。当初は ISO 2 種類（通常版とデュアルブート版）・仮想マシンでの利用は想定しない（2026-11-20 ユーザー決定）だったが、2026-11-21 の決定でビルドは 5 種類（64bit 版、32bit 版、ARM 版、Live ブート版（USB）、仮想環境版）に改め、仮想環境版は正式な配布物とする。パーティションの画面は出す。自動で分けることも選べる

### 3.4 リポジトリ構成（GitHub）

```

├── kernel/        カーネル
├── boot/          ブートローダー設定、Limine
├── drivers/       デバイスドライバー
├── fs/            ファイルシステム
├── net/           ネットワーク
├── gui/           デスクトップ、ウィンドウ管理、テーマエンジン
├── apps/          標準アプリ
├── shell/         2体系対応シェル（v0.1で土台あり）
├── config/        theme.toml などの既定設定（v0.1で土台あり）
├── installer/     インストーラー、ISO作成
├── tests/         ユニットテスト、起動テスト、UIテスト
├── docs/          設計書、この仕様書、ユーザー向けヘルプ

```

（実装の実態に合わせた注記、2026-11-22）実際のツリーは上記の計画とは異なり、カーネルとドライバは `kernel/`、シェルと互換レイヤーは `shell/`、32bit 版は `kernel32/`、ARM 版は `kernel/arm/` に集約されている。`boot/` `fs/` `net/` `gui/` `apps/` `config/` `installer/` という独立ディレクトリは存在せず、ファイルシステム・ネットワーク・デスクトップは `kernel/` 内、インストーラーはシェルコマンドと画面アプリとして実装されている。ドライバの後付けパッケージのソースは `drivers/` にある。

## 4. セキュリティ（しっかり、が具体的に何か）

**方針（2026-11-20 ユーザー決定）：市役所レベルの Enterprise レベルのセキュリティを標準で適用する。** 企業・自治体で使える水準を、家庭の PC でも既定でオンにする。便利さのために緩めない。
- Enterprise 機能はすべて標準で入れる。変更は管理者権限があるアカウントだけができる（2026-11-20 ユーザー決定）
- デバイスの一括管理：管理者が全 PC の設定・更新・アプリをまとめて管理できる
- 監査ログ：誰がいつ何をしたか記録して、改ざんできない形で保存する
- USB・外部メディアの制限：許可した USB だけ使えて、データの持ち出しを防ぐ
- ディスク暗号化を必須にして、回復キーを管理者が預かる
- アプリの許可リスト：管理者が許可したアプリだけ動く
- パスワードのルールとロックアウト：失敗回数でロック、多要素認証も使える
- 遠隔ロック・消去：PC をなくしたときに遠隔でロック・消去できる
- セキュリティ更新の集中管理：管理者が全 PC の更新タイミングを決める
- 耐量子暗号：量子コンピューターの時代でも安全な暗号を使う。ファイル暗号化の AES-256 と SHA-256 は量子コンピューターにも強いとされるためそのまま使う。更新ファイルの署名には耐量子署名（ML-DSA）、将来の鍵交換には耐量子鍵交換（ML-KEM）を使う（2026-11-21 ユーザー決定。セキュリティ強化フェーズのあとで実装する）

### 4.1 起動とディスク

- セキュアブート：署名されたブートローダーとカーネルだけ起動する
- ディスク暗号化：既定でオン（ユーザーがオフにできるが、警告を出す）。パスワードを忘れた場合の回復キーの案内
- 検証済みブート：システムファイルが改ざんされていたら起動を止めるか警告する
- 復旧モード：暗号化解除、起動修復、初期化（データを残す／消すを選べる）。復旧モードの選択肢は「データを残して直す」「復元ポイントに戻る」「初期化する」に加えて、「GitHub Releases にあるひとつ前のバージョンからダウンロードして、破損したファイルだけ修復する」も入れる（2026-11-20 ユーザー決定）

### 4.2 アカウントと権限

- 複数ユーザー、ゲストユーザー、保護者による制限（子供用アカウント）
- 管理者と一般ユーザーの分離。管理者権限が必要な操作はその場で確認する
- アカウントはローカルのみ。Prism アカウントやクラウド同期は作らない（2026-11-20 ユーザー決定）
- アプリごとの権限：ファイル、カメラ、マイク、位置情報、ネットワーク、通知、クリップボード。許可は後からいつでも変えられる
- パスワード、PIN、生体認証、2 段階認証（対応サービス）

### 4.3 アプリの隔離

- 互換レイヤーで動く外部アプリ（ゲスト）はサンドボックスで動く（リング 3、専用ページテーブル、システムコールのファイル経路制限、ウォッチドッグ）。1 つのゲストが落ちても、他のアプリや OS には影響しない（`make compat-test` で悪意・暴走ゲストを使って検証済み）
- 内蔵のデスクトップアプリは現状では隔離されていない（カーネルと同じアドレス空間で動く関数群のため）。隔離にはアプリごとのアドレス空間と IPC が必要で、未実装であることを明記する（2026-11-22 精査で確認。チェックリスト項目13の残件）
- ゲストは保護ファイル（アカウント、設定、許可リスト、監査ログ、鍵ファイル等）を読めない。書き込みはその実行中に自分が作ったファイルだけに限る
- ストアのアプリは署名チェックと審査を通す。外部から入れたアプリは警告を出して、実行するかどうかユーザーが決める

（既定値の実態、2026-11-22）チェックリスト項目6の「既定でオン」は、ファイル暗号化・権限（許可リスト）・互換ゲストのサンドボックス・署名付き更新の検証が、設定を変えなくても有効であることを指す。一方、設定項目 `auto_security`（セキュリティ関連の自動処理をまとめて有効化する任意設定）は実装の既定がオフであり、上記の保護自体のオン/オフとは別物である。

### 4.4 ネットワークとプライバシー

- ファイアウォール：既定でオン。アプリの通信は許可リストで管理
- 暗号化通信（HTTPS）を優先し、安全でない接続は警告する
- 位置情報・診断データ・利用データの収集は既定で最小限。送るかどうかは設定で選べる。何を送っているか設定画面で見られる
- 診断データ・利用データ（テレメトリ）は、とりあえず送らない（なし）。後で入れるときは既定オフで、送るものを明示する（2026-11-20 ユーザー決定）
- トラッキング防止、広告識別子の管理

### 4.5 マルウェア対策と更新

- マルウェア検査：ダウンロードしたファイルとアプリの検査、定義ファイルの自動更新
- 署名付き更新：OS とアプリの更新は署名を確認してから入れる。署名が合わなければ入れない
- セキュリティ更新は自動で届く。緊急の更新はすぐに、通常の更新はユーザーの選んだ時間に
- 更新に失敗したら自動で前の版に戻る（ロールバック）
- 脆弱性の報告窓口と、修正までの手順を決めておく

### 4.6 監査と復旧

- 監査ログ：ログイン、権限の変更、アプリのインストールを記録（ユーザーが見られる）
- バックアップ：ファイル履歴、システムの復元ポイント、クラウドへのバックアップ（任意）
- 紛失・盗難時：デバイスの暗号化と、遠隔ロック／消去（対応する場合）
- パスワードを忘れた場合の回復手順（回復キー、管理者によるリセット）

### 4.7 ビルドと配布のセキュリティ（GitHub Actions）

- 依存関係の固定（バージョンを決め打ちする）、脆弱性スキャン（Dependabot 風）
- ビルドはクリーンな環境で、再現可能ビルドを目指す
- リリースは署名付きで、チェックサムを公開する
- シークレット（鍵・トークン）はリポジトリに入れない。GitHub の Secrets を使う
- プルリクエストはレビューと CI（ビルド＋テスト＋セキュリティ検査）が通ってから取り込む

## 5. その他

### 5.1 パフォーマンス目標

- 起動 30 秒以内、ログイン後 10 秒以内に操作可能
- アプリの起動：ブラウザ 3 秒以内、ファイルマネージャー 1 秒以内を目安
- アイドル時のメモリ使用量を抑え、バッテリー駆動で 8 時間の通常利用を目安
- 100 個のウィンドウを開いても操作が重くならないこと

実測（2026-11-22、QEMU・256MB、`scripts/perf-measure.py`、詳細は docs/PERF_MEASUREMENT_2026-11-22.md）：起動 5.6 秒、ブラウザ表示 0.36 秒、ファイル表示 0.37 秒、アイドル時メモリ使用 約 2.0MB。バッテリー駆動時間は QEMU にバッテリー機器が無く未検証（実機待ち）。「ウィンドウ 100 個」は本 OS の画面モデル（アプリ画面＋浮動ウィンドウ）と構造が違うため、アプリ切替時間と再描画方式で代替評価した。

### 5.7 非目標（v1.0 ではやらない、と決めておくもの）

- 他の OS のアプリの完全互換（27H2 で本格化。§5.6 のロードマップ参照）
- サーバー用途（v1.0 はデスクトップ専用）
- スマートフォン／タブレット版（v1.0 は PC 専用）
- 独自のクラウドサービス（既存のクラウド連携にとどめる）。アカウントもローカルのみで、Prism アカウントは作らない
- 仮想マシン向けの最適化（準仮想化ドライバの網羅等）は非目標。ただし仮想環境版のビルド自体は 2026-11-21 決定で正式な配布物に含める（§5.6 参照）
