## 観点1：今フェーズの新規コード

### 新規発見
- **TLS の全秘密が「決定的・再種入れなし」エントロピープール由来**（`kernel/security.c:64-95`、`kernel/shell.c:3092-3108`、`kernel/tls.c:937,1094,1105-1112`）。プールは起動時に1回だけ種入れ（RDRAND 64bit×1、RDTSC下位、RTC秒、総ページ数）され、以降は `SHA-256(プール‖カウンタ)` を返すだけ。ClientHello random（平文で送信）・premaster・PKCS#1パディングが全てこの源。RDRAND 無し環境では ClientHello random から種候補を列挙照合できれば premaster まで復元でき、セッション復号につながり得る（構造的事実。プール自体の決定性は旧監査にあったが、TLS秘密への影響経路は新規）。同じ源は persist の IV 生成（`kernel/persist.c:131`）にも使われる。
- **IMAP タグ完了判定が `" OK"` の部分文字列一致**（`kernel/mailproto.c:537`）。`a001 NO... OK` のような行も成功扱いになり、LOGIN失敗を成功と誤認し得る。
- **IMAP 数値パースに桁あふれ検査なし**（`kernel/mailproto.c:556-565,539-547`）。リテラル長・EXISTS数が無制限蓄積で符号付き溢れ→小さい正値に回り込むとストリーム同期ずれ。リテラル開始判定も「`*` で始まり `{` を含む行」だけで FETCH/BODY の検証なし。
- **リテラル無しの FETCH 成功で空メールを「受信した」ことにする**（`kernel/mailproto.c:714-724` 付近）。
- **RSA modulus の下限チェックなし**（`kernel/tls.c:1096,1102`）。51B未満の modulus で `ps_len` が size_t アンダーフローし、スタック `enc[512]` へ巨大書き込み。到達には「小さい鍵の証明書がピン設定されている」前提が必要。`tls_open` の host 長も API 単体では無検査（現行呼び出し側は64B字段で制限され到達不可）。
- **`pass_enc` の限界**：AES-256-CTR で MAC なし（改ざん検出不可、ビット反転が平文パスワードに直結）。PIN 未設定時は `pass=` 平文保存へのフォールバックが実在（`shell/mail.c:196-201`、コード内明記の仕様。旧監査の「平文パスワード」の精密化）。鍵導出自体（PIN→KDF 10000回）は健全。
- **TLS 秘密が使用後・切断時に消去されない**（`kernel/tls.c:1091,1131,1360-1369`。premaster/master/セッション鍵が静的構造体に残留）。
- **** GHASH/AES/RSA は非定数時間（`kernel/tls.c:234-243` 等）。遠隔タイミング攻撃の現実性は低いと推測されるが実証なし。
- **監査ログ：ログイン前イベントが RAM のみに保持され、セッションが成功ログイン前に終わると失われる**（`kernel/shell.c:1565,1606-1641`）。保留バッファは最大16件で満杯時は最古を無言で破棄。アカウント破損時の `prism_halt()`（同:331-334）やロックアウト中の電源断では、失敗ログイン/ロックアウトの記録がディスクに一切残らない。flush は成功ログイン後の2箇所（同:3142,3179）のみ。
- **ショートカット取り込みが矢印キーも割り当て対象に含む**（`kernel/desktop.c:4741` の `c >= 0x81` は PRISM_KEY_UP/DOWN/LEFT/RIGHT=0x90-0x93 を含む）。起動判定（同:4821）が各画面のキー処理より先に走るため、矢印に割り当てるとカーソル移動・選択が各アプリとショートカットページ自体で壊れる。除外も警告もなし（復旧はページ内の '0' リセット可）。
- **`settings_key_parse` の F番号蓄積が範囲検証前に int 溢れし得る**（`kernel/settings.c:116-`。長い数字列で符号付き溢れ＝UB、実務上は巻き戻って拒否）。ファイル経由の重複割り当ても未排除（取り込みUIは入れ替えで防ぐがパーサは防がない）。

## 観点6：5種バリアント間の機能差

### 問題なし（確認）
- **Live版・仮想環境版に機能欠落なし**：Live は ISO のバイト同一コピー（`Makefile` live-usb は `cp` のみ）、VM版は通常64bitカーネル＋PRISMFSディスクの qcow2 変換のみ。
- 32bit のシェルコア共有は本物（K32_SRCS に `shell/core.c, vfs.c` が入り、`main32.c` は `prism_shell_execute` を呼ぶ。コアコマンドの欠落なし）。

### 新規発見（既知分を超える差分）
- **ARM版のディスク永続化は平文**（`kernel/arm/main.c:487` で `arm_disk.crypto = NULL` を明示。64bit の persist は利用者ファイルを暗号化）。既知リストに無い差分。あわせて ARM にはログイン/PIN/アカウント（`account.c, persist.c` 未リンク）も監査ログ暗号化も無い。
- **ARM版の欠落は「対話操作・壁紙」よりはるかに広い**：拡張コマンドは独自5+2個（disk系＋net/fetch）のみで永続化は手動 `dsync/dload`。`shell/` のアプリ系が全滅 — 事務系（sheet/doc/docx/pptx/slides/zip）、mail、update、install、互換/サンドボックス、ML-KEM/ML-DSA、TLS、cards/shooter/video/wav、回復モード、横断検索が全て無い。時刻は `kernel/arm/rtc_stub.c` が起動後経過秒ベースで日付は常に1月1日（監査時刻等が無意味）。PCI 自体が無く USB/AHCI/e1000/FAT16/block層も無い。
- **32bit版の欠落も「画面/ディスク/ネット」より広い**：リンクされるのは kernel32＋`shell/{core,vfs}`＋`kernel/{string,security,crypto,settings}` のみ。拡張コマンド（install/passwd/security/audit/snapshot/update/mail/pq/run/compat/recovery/net/disk/usb/fetch 等）は全て欠落、`diskfs.c` も無いため永続化・スナップショット・暗号化の経路が丸ごと無く、`theme` の settings.txt も起動毎に初期状態。ログイン/アカウントなし。メモリ管理は PMM/heap でなく静的アリーナ2MB（`kernel32/alloc.c:11,20`）。
- **Live版には再起動を跨ぐ永続化領域が無い**（検証も同一セッション内の RAM VFS 書込まで。`scripts/live-usb-test.py:207-209`）。「Live版として作業保存はできない」が残りリストに無い。

## 優先度つき総括

1. **サンドボックスの穴2件（高）**：細工ELFの vaddr 無検証によるカーネル上半分到達経路と、ゲストからの全VFS読み書き（`.account` 差し替え可能）。チェックリスト項目6「合格」の前提（隔離が効いている）を揺るがすため最優先。どちらも未検証領域だったことがテスト面でも裏付けられた。
2. **TLS の乱数（高・条件付き）**：決定的プール＋再種入れなしが TLS 全秘密の源。RDRAND 前提の明記か、接続ごとの再種入れ/ハードウェア乱数の都度混合が要る。

5. **ARM の平文ディスク保存（中）**：バリアント間のセキュリティ差分として新規。
6. **監査ログのログイン前イベント喪失（中）**、**IMAP の " OK" 部分一致・数値溢れ（中）**、**A4 の終端検証欠落（中）**。
