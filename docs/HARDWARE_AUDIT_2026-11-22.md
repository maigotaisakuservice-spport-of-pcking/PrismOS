# PrismOS ハードウェア対応 精査報告（2026-11-22）

調査方法：`~/workspace/prismos/` の全ソース（kernel/、kernel/arm/、shell/、Makefile、scripts/）を grep とファイル読みで確認した読み取り専用調査。ビルド・QEMU実行は行っていないため、「対応済み」はコードの実在をもって判定し、動作の合否は既存テストの存在範囲でのみ言及する。

注意（スナップショット性）：調査時点でも別エージェントが同じツリーで開発中であり、Makefile や scripts/ には調査当日の新規ファイル（`scripts/live-usb-test.py`、`scripts/vm-test.py` 等）が含まれていた。5種ビルド（32bit等）・サンドボックス・Live USB・仮想環境版は進行中のため、本報告の該当箇所は調査時点の状態である。

凡例：
- 状態：**対応済み**（ドライバコードが実在）／**部分対応**（あるが制限が大きい）／**未対応**（コード自体がない）
- 検証：**QEMU可**（QEMUのエミュレーションで検証できる）／**実機のみ**（実ハードウェアがないと確認できない）
- 出典：**監査済み**＝2026-11-21監査（docs/LIMITATIONS_AUDIT_2026-11-21.md）に項目あり／**新規**＝今回新たに見つけた観点・抜け

## 10. ARM版のハードウェア対応まとめ

`kernel/arm/` にあるのは entry / uart（PL011）/ gic / timer / mmu / ramfb / main のみ。ディスク・ネットワーク・USB・PCI・デスクトップアプリは ARM では動かない（監査済み 未実装#83-86）。画面は ramfb で描画のみ（壁紙＋タスクバーの静的描画、`kernel/arm/main.c:103-136`）。ファイルシステム永続化もなし（RAM VFS のみ）。

## 11. ドライバの後付けインストール機構（メーカー製GPUドライバ方式の前提）

### 現状：仕組みは存在しない

1. **カーネルモジュール機構なし。** 全ドライバは `Makefile:64-82` の `KERNEL_C_SRCS` として列挙され、`kernel.elf` に静的リンクされる（ata / ahci / virtio_blk / e1000 / uhci / sb16 / fb 等すべて）。実行時にドライバを追加・差し替え・取り外すコードは grep で確認できず、存在しない。
2. **ブートローダ経由のモジュール受け渡しも未使用。** `kernel/limine.h:481-507` に Limine モジュールの構造体定義はあるが、`kernel/main.c` はモジュールリクエストを発行していない。
3. **更新システムは「ファイル＋カーネル全体」の差し替えまで。** `shell/update.h:14-45` のマニフェストは通常ファイルとカーネルイメージ（`kernel` 行、FAT16 ブート区画への差し替え）のみ。ドライバ単体のパッケージ形式・配布単位はない。ドライバを直すにはカーネル全体の更新になる。
4. **互換レイヤーは流用できない（そのままでは）。** `shell/compat.c` は静的 ELF のユーザープログラム用ローダで、PT_LOAD の配置のみ・リロケーションなし。しかも `shell/compat.h` の明記通りゲストはカーネルと同じ権限で動き、隔離はない。ELF 解析の部品としては参考になるが、カーネルドライバ用ローダではない。
5. **配布の受け口なし。** Prism Store・パッケージマネージャは未実装（監査済み 未実装#26、#42）。
6. **流用できる土台はある。** ML-DSA-44 署名検証（`shell/mldsa.c`、更新マニフェストで実働）、更新の差分・ロールバックの仕組み（`shell/update.c`）、ファイル配信の経路（HTTP取得＋SHA-256検証）は、ドライバパッケージの署名検証・配信に応用できる。

### メーカー製GPUドライバを「ユーザーがダウンロードして入れる」方式に必要なもの

1. **ドライバパッケージ形式**：ドライバ本体（カーネル空間コード）、対応 PCI ID 一覧、バージョン等のメタデータの定義。
2. **カーネル側動的ローダ**：ELF のリロケーション処理を含む本物のローダ（現 compat ローダにはない）。
3. **カーネル内部 API の定義とバージョン管理**：ドライバが使う PCI / PMM / フレームバッファ等の関数インターフェースを固定し、互換性を管理する仕組み。
4. **ドライバの登録・初期化・デバイスバインド**：現 `kernel/pci.c` は「探す」だけで、デバイスをドライバに割り当てる概念がない。probe/init の枠組みが要る。
5. **GPU固有の所有権切り替え**：`kernel/fb.c` はブートローダ提供の単一 FB 前提。GPUドライバがモード設定と描画を引き継ぐための受け渡し API が要る。
6. **署名検証の必須化**：カーネル空間で動く外部コードのため、ML-DSA 署名なしドライバを拒否する仕組み（土台はあり）。
7. **障害時の扱いの方針**：カーネル空間で動く以上、ドライバのバグは OS 全体を落とす。隔離（サンドボックス）は現在未実装で、少なくとも「落ちたら再起動して問題のドライバを無効化する」等の回復策が要る。
8. **配布経路**：Prism Store か更新システムの拡張（どちらもドライバ単位の配布は未対応）。

結論：必要な仕組みは現状ほぼゼロから作る必要がある。既存資産で使えるのは ML-DSA 署名検証、更新の配信・ロールバックの考え方、ELF 解析の一部のみ。

## 12. 今回新たに見つけた抜け（2026-11-21監査との差分）一覧

監査に項目自体がなかったもの：
1. **SMP / マルチコア / APIC が丸ごと未対応**（監査には CPU の項目が存在しなかった）
2. **NVMe ドライバなし**
3. **SD / SDHCI / MMC なし**
4. **virtio-net なし、有線 NIC は e1000（82540EM 1機種固定）のみ**
5. **HD Audio（intel-hda）なし**
6. **virtio-gpu / VBE なし、OS 起動後の解像度変更なし**
   - 前提条件 (2026-11-22 記録): QEMU の virtio-gpu には 8.1〜10.2.3 に
     整数オーバーフロー群があり、修正は QEMU 11.0 のみ。ハードウェア
     フェーズで virtio-gpu を採用する場合は **QEMU 11 以降を前提**に
     すること (検証環境の QEMU を 11 未満のまま採用しない)。
7. **ブロック層が単一ディスク前提**（2台目のディスクを使えない）
8. **スワップなし、汎用仮想メモリなし**（paging.c は MMIO 写像専用）
9. **PCIe ECAM なし**（レガシー PCI 設定アクセスのみ）、**ARM に PCI なし**
10. **TPM なし**
11. **USB ハブ / USB オーディオ / USB プリンタ / UVC のクラスドライバ観点**
12. **シリアル COM1 固定**（COM2 以降なし）
13. **x86 に定期タイマ割り込みなし**（PIT ポーリング主体）
14. **PS/2 キーボードが US 配列前提**（JIS マップなし）
15. **ARM MMU の写像範囲が 2GB まで**
16. **タブレット（virtio-tablet 等の絶対座標デバイス）なし**

監査後の変化（監査時点から状態が動いたもの）：
17. **Live USB / 仮想環境版のビルドターゲットが Makefile に追加済み**（監査 未実装#76・#77 は解消方向に進行中。本調査は読み取り専用のため、テスト合否は未確認）
18. **ARM ramfb はコード上で fw_cfg DMA 方式に修正済み**（監査 未検証#1 の「証拠矛盾」は解消方向。実行確認は本調査の範囲外）
19. **ARM MMU の写像範囲（#15）は解消済み**（2026-11-22）：L1 の 1GB ブロックを DTB の RAM 末尾まで並べる方式に変更（上限は物理アドレス 36 ビット = 64GB）。あわせて決定的な不具合を発見・修正：QEMU は ELF カーネルには起動規約を適用せず x0=0 で渡すため DTB パースが常時失敗し、従来は 256MB フォールバックで隠れていた。カーネルを AArch64 イメージヘッダ付き raw バイナリ（kernel-arm.bin）で起動する方式に変え、DTB が本当に渡るようにした（DTB 領域は PMM からも除外）。QEMU `-m 4096` で PMM 1,048,093 ページ（約4GB）を確認し、arm-boot-test / arm-disk-test / arm-screen-test が 4GB 構成でも PASSED。256MB 構成の回帰も全テスト PASSED。

監査済みで本調査でも状態が変わっていない主なもの：Wi-Fi / Bluetooth ドライバ自体なし、EHCI / xHCI なし、USB は列挙のみ（HID入力・ストレージなし）、プリンタ・スキャナなし、タッチ・ペンなし、電源管理なし、指紋・顔認証なし、GPU アクセラレーションなし、マルチモニターなし、ディスク全体暗号化なし（ファイル単位のみ）。
